## Learned

- **Drizzle ORM (TS)**: Schema-first ORM — define tables with `pgTable()`, query with `db.select().from(table).where(eq(...))`. No migrations needed yet (schema created at runtime). Feels like writing SQL in TypeScript with type safety.
- **SQLAlchemy async (Python)**: `create_async_engine()` + `async_sessionmaker` + `expire_on_commit=False`. The async session pattern: `await session.execute()`, `await session.commit()`, `await session.close()`. Must `await` everything — `session.get()` is async too!
- **Drizzle `postgres` driver vs `pg`**: Chose `postgres` (a.k.a. `postgres.js`) because it's a single package with native async/await, no connection pool config needed. `pg` (node-postgres) requires `@types/pg` and a separate pool setup.
- **SQLAlchemy `server_default`**: Use `text("now()")` for PostgreSQL's `NOW()` — can't use Python's `datetime.now()` as server default since the DB generates the value.
- **Pydantic `model_validate()`**: Bridge between SQLAlchemy model rows and Pydantic types — `Workspace.model_validate(row)` converts a DB row to a Pydantic model with validation.
- **Drizzle `.returning()`**: After `.insert()`, chain `.returning()` to get the inserted row back (like PostgreSQL's `RETURNING *`). Needed to get the `created_at` timestamp the DB generated.
- **FastAPI startup event**: `@app.on_event("startup")` is the right place for `init_db()` — ensures tables exist before any request hits. Python `main()` stays clean.
- **Session lifecycle bug**: Async sessions must be explicitly closed in `finally:` blocks. `async_session()` returns a coroutine — forgetting `await` means you're working with a coroutine object, not a session.

## Broke & Fixed

### Python `generate_id` vs `generate_id()` (function reference bug)
In `saveWorkspace` and `saveIssue`, wrote `id=generate_id` instead of `id=generate_id()`. This passed the *function object* as the ID string, so the DB got something like `<function generate_id at 0x...>` instead of a UUID.
**Fix**: Added `()` to call the function. Python doesn't warn about this at all — it's a silent bug.

### Missing `await` on `session.get()` (async session bug)
All `delete*` and `find*ById` methods called `session.get(Model, id)` without `await`. SQLAlchemy's async `session.get()` returns a coroutine. Without `await`, it returns `None` or a coroutine object, silently breaking the query.
**Fix**: Added `await` to all `session.get()` calls.

### Missing `await` on `get_session()` 
`get_session()` returns `async_session()` which is a coroutine. Calling it without `await` gives you a coroutine object, not a session. Every method that does `session = get_session()` was actually getting a coroutine.
**Fix**: Changed all `session = get_session()` to `session = await get_session()`.

### `session.execute()` returns Result object not row
`findWorkspaceById` was treating `await session.execute(select(...))` as the row directly. But `execute()` returns a `Result` object — you need `.scalar_one_or_none()` or `.scalars().all()` to extract rows.
**Fix**: Added `.scalar_one_or_none()` to single-row queries.

### Session connection leak
Sessions were created but never closed. Each request would leak a DB connection until the process died.
**Fix**: Wrapped all session usage in `try/finally: await session.close()`.

### Duplicate `init_db()` call
`main.py` was calling `init_db()` manually AND `server.py` had a FastAPI startup event also calling it. Double table creation attempt.
**Fix**: Removed manual call from `main.py`, let FastAPI's startup event handle it.

### Port conflict TS vs Python
Both tracks tried to bind to port 8000.
**Fix**: Python track moved to port 8001.
