## Learned

- **Fastify vs FastAPI parity**: Both frameworks follow the same pattern — create app, register routes with decorators/methods, bind to port. Fastify uses `app.get()` with callback, FastAPI uses `@app.get()` decorator. Both return JSON automatically.
- **`@fastify/swagger`**: TypeScript track gets auto-generated OpenAPI docs (like FastAPI's built-in `/docs`). Will be useful for API-first design later.
- **`uvicorn.run()` is synchronous**: Unlike Fastify's `app.listen()` which returns a Promise, uvicorn's `run()` blocks. The Python `main()` stays sync, no `asyncio.run()` wrapper needed.
- **`uv run` vs `uvicorn`**: `uv run uvicorn src.server:app` works directly — uv handles the virtualenv activation automatically. No `source venv/bin/activate` step.
- **Service DI pattern (Hoppscotch reference)**: Creating repo instances at module level and injecting into routes mirrors Hoppscotch's service dependency injection pattern.

## Broke & Fixed

### `await app.listen()` missing (TS)
The `startServer` function called `app.listen({ port })` without `await`. Fastify's `listen()` returns a Promise — without awaiting, the function returns immediately and the console.log fires before the server is actually listening.
**Fix**: Added `await` before `app.listen({ port })`.

### `await uvicorn.run()` invalid (Python)
`uvicorn.run()` is a sync blocking function that returns `None`. Putting `await` in front of it throws `TypeError: object NoneType can't be used in 'await' expression`.
**Fix**: Made `main()` a regular sync function, removed `asyncio.run()` wrapper.
