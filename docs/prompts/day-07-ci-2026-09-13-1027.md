## The DB Question (settle this first — it shapes half the day)

Today's roadmap row says `pytest` + `tsc --noEmit`. The app is *database-shaped* (every route calls the repo). Three candidate answers:

1. **ASGI transport, no DB** — `httpx.AsyncClient(transport=ASGITransport(app=app))` lets tests call the app in-process with zero infrastructure; only test what can be tested without a connection (health, validation-failure 422s, the 404-on-missing-ID path *if* the handler 404s before it would otherwise fail… which it does *not* — the repo call raises first). Note the trap: `GET /workspaces/{id}` with a fake ID will hit the DB and raise `DatabaseCrashError` → 500, *not* 404, when there is no database. So "contract" tests of the *DB path* are not fully representable without a DB.
2. **SQLite via SQLAlchemy for Python tests** — `sqlalchemy` is already a dependency; an async `aiosqlite` engine + `Base.metadata.create_all` in a conftest fixture would let the full route→repo→DB path run in-process with a disposable file DB. Cost: adds one dev dependency (`aiosqlite`), and the TS side (postgres.js, not SQLAlchemy) has *no* SQLite path — the dual-language parallel **breaks**: py gets full path tests, ts gets type-check + contract-surface tests only. The breakdown must face this asymmetry honestly rather than pretending symmetry.
3. **Postgres service container in CI** — `services: postgres` in the workflow + real `DATABASE_URL` + a schema-push step. This is the *true* end-state for "make it right," and it is also the most CI money/complexity for a "make it work" day. It is a valid pick *if* the breakdown argues the alternative leaves the day's own "is my code actually running" bar unmet.

**Requirement**: the breakdown must choose one of the three (a fourth is fine if defensible) and must state the dual-language consequence of that choice in one line — because per ADR-001 the two tracks run the same *concepts*, not the same *test count*. Never silently let one track have stronger tests than the other without naming it.
