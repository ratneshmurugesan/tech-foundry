# docs_v2 — where the v2-era docs live

## The actual change
`docs_v2/` is the write-side home for new-era docs: day notes, ADRs,
the debt ledger, the manifest. The v1-era tree (`../docs/`) is **untouched
history** — read-only. Anything here that needs a v1-era file *links* to it,
never copies it (a copy is a second source of truth, and the second copy rots
— that is the 2026-09-21 lesson; see Rule 2 below).

The whole of it:

```
docs_v2/
├── README.md       ← this file: orientation + the EOD procedure
├── daily-flow.md   ← your daily operating sheet: the full cycle in one file
├── debt.md         ← THE debt ledger: one row per debt, greppable in one glance
├── llms.txt        ← the manifest — GENERATED by gen_llms.sh; humans never edit it
├── gen_llms.sh     ← the generator (3 hand-touched lines; everything else derived)
├── adrs/           ← v2-era ADRs
└── notes/          ← v2-era day notes (day-*.md) + standing notes (non-day files,
                      always listed under llms.txt's "Standing notes")

../docs/ (read-only v1-era history)
├── adrs/  (ADR 001 onward, incl. the ADR-101 process doc)
├── notes/ (day-01 through the razorpay day)
├── prompts/ (incl. master.md — still the 18 standing rules)
└── roadmaps/v4/master.md ← THE single living roadmap; EVERY day gets one row here
```

## The two rules the whole shape exists to enforce
1. **A debt lives in exactly one row, in one place** (`debt.md`). Any ADR /
   note that defers something *links the row* — it never re-states
   the payoff condition. The 11a/11b/11c debts lived in 15+ re-statements
   across three docs and drifted into an invented "2026-10-10" date and an
   invented close; the roadmap is a *single line per day*, not a re-derivation
   of it. One row cannot drift.
2. **The manifest is derived, not written** (`gen_llms.sh` → `llms.txt`).
   The one hand-written manifest that ever existed (2026-09-21) fabricated a
   decision inside two days. The generated one cannot: it copies filenames
   and `Status:` lines, it never *re-thinks* them. A stale manifest is still
   better than a wrong one — that is why the EOD step is a script, not a memory.

## The EOD procedure (the entire ritual; ~5 minutes)
1. **Note** — `notes/day-NN-<theme>-<YYYY-MM-DD>-<HHMM>.md`: built / didn't-build /
   decisions / debt (3–5 lines), shaped like `../docs/notes/TEMPLATE.md`.
2. **ADR** — only if a real *code/tech* decision was made: `adrs/adr-NNN-…-theme.md`
   (ADR-lite, 12 lines; shape in `../docs/adrs/TEMPLATE.md`). Doc-format or
   process changes get a line in the note, never an ADR.
3. **Debt** — one `debt.md` row update: anything deferred *becomes* a row;
   anything claimed/closed flips status to `done (link note)` or `dropped (link ADR)`.
4. **Roadmap** — one line in `../docs/roadmaps/v4/master.md` + its NEXT.
5. **Manifest** — `sh gen_llms.sh`, then `git add -A` and **show the diff + propose the
   message**. Rule 13: the agent never commits; the commit is the human's act.

No 25-step ritual. Rules 1 and 2 do the work; the procedure is just the
places they touch.
