# Day 17 (2026-11-06) — the first human surface: a browser can now use the restaurant

**Built** (the web kitchen, new):
- **Next.js 15 + Tailwind CSS 4 + Auth0 React SDK** — a new `apps/taskflow/web/` kitchen (third kitchen, the *dining room*): a full SPA that talks to the TS kitchen via a Next.js rewrite proxy (`/api/*` → `taskflow-ts:8000`). No CORS, no absolute URLs in the browser.
- **Workspaces dashboard** (`/workspaces`): the first-run UX law — logged out → one login button; logged in, empty → inline "Create your first workspace"; has workspaces → card grid. React Query for data, Auth0 for the badge.
- **Workspace detail** (`/workspaces/[id]`): lists the workspace's projects (via the flat scoped `GET /projects` route, filtered client-side by `workspace_id`), with a create-project form.
- **Board view** (`/workspaces/[id]/projects/[projectId]`): issues in a two-column board (open / closed) with a toggle to move between columns. Uses the flat scoped `GET /issues` route, filtered client-side.
- **Settings page** (`/workspaces/[id]/settings`): displays the current plan tier + state; the checkout button (owner-only) calls `POST /billing/checkout` and opens Razorpay's checkout in a new tab.
- **API client** (`lib/api.ts`): a thin `fetch` wrapper that attaches the Auth0 access token as a Bearer badge and parses the ADR-007 error envelope. One function, no SDK.
- **Types** (`lib/types.ts`): mirrors the backend wire contract — `Workspace`, `Project`, `Issue`, `WorkspaceMember`, `Plan`, `CheckoutResponse`.
- **Docker compose integration**: `taskflow-web` service in both the dev chart (hot mount + `npm run dev`) and the prod overlay (baked image + `npm start`). The web container reaches the TS kitchen by compose service name.

**Fixed** (the TS kitchen, one real bug):
- **`findMembership` was filtering on the wrong column** — `workspaces.id` instead of `workspaceMembers.workspace_id`. The PATCH/DELETE routes re-checked membership with the *resource* id (issue/project) rather than the workspace id, so every owner edit threw `ForbiddenError` → 500 (the error handler had no 403 case). The authorize middleware already resolves issue→project→workspace and enforces the role, so the route-level re-check was a broken duplicate — commented out to match the PY kitchen (the A.2 "middleware-only" shape from day-12). Added the missing `ForbiddenError → 403` case to the error handler for parity.

**What I learned** (the day's real cost):
- **The dining room is a third kitchen, not a fourth language.** The parity wall (ADR-001) still holds between the two *backend* kitchens; the web app is a *client* that speaks to one of them. The restaurant analogy extends: the kitchen (TS/PY) cooks; the dining room (web) serves. The parity guarantee means the dining room doesn't care which kitchen it's in front of.
- **The flat scoped routes are the right shape for a client.** The nested routes (`GET /workspaces/:id/projects`) 404 in the current backend; the flat routes (`GET /projects`, `GET /issues`) return *all of the badge-holder's* rows, and the client filters by `workspace_id`. This is a deliberate trade-off: one extra filter in the browser vs. a new backend route. For a small product, the client filter is the thin version.
- **The rewrite proxy kills the CORS problem for free.** `NEXT_PUBLIC_API_BASE = "/api"` + a Next.js rewrite to `BACKEND_URL` means the browser sees same-origin requests. In compose, `BACKEND_URL = http://taskflow-ts:8000` (service name); in bare dev, `http://localhost:8000`. No CORS headers needed on the backend.

**What's left** (the honest remainder):
- **Issue create/edit** (roadmap day 21-22): the board has a toggle (open↔closed) but no create form and no edit. `Cmd+N` to create, a basic title+status form — the next day's work.
- **Board drag** (roadmap day 19-20, "basic drag"): the toggle works; drag-to-move is not yet wired. A `dnd-kit` or native HTML5 drag would close this.
- **Deploy full stack** (roadmap day 25-26): the compose chart has the web service, but the *single-URL* deploy (a reverse proxy in front of the web container, the backend containers behind it, one public URL) is not yet done. The $0 Free Tier VM story from day 6 needs a third container + a Caddy/nginx front.

**The bar** (ADR-101): the restaurant now has a dining room. A human with a browser can sign in (Auth0), see their workspaces, enter one, see its projects, open a board, toggle issues, and buy a plan. The two backend kitchens are untouched in their parity contract; the one TS fix (the broken `findMembership` filter) brings the TS kitchen *closer* to the PY shape, not further. The web app is a new surface with no parity obligation (there's no "PY web" to be in parity with) — it speaks the wire contract, which the golden matrix already guarantees is identical from both kitchens.
